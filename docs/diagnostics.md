# Диагностика без ноутбука

В Settings вверху расположен **Report a problem**. Эта же форма доступна из сообщения об ошибке открытия доступа к медиа в онбординге.

1. Опиши, что нажал и что произошло. Если приложение упало — сначала запусти его снова.
2. Нажми **Send report / Gmail**: ZIP будет создан автоматически.
3. Выбери Gmail и отправь подготовленное письмо с вложением.

На автомобиле нужно установить Gmail и войти в почтовый аккаунт. Получатель подставляется из сборки; его можно изменить в форме. Открытие окна Gmail ещё не означает отправку: нужно нажать Send. Сеть нужна для доставки письма, сбор ZIP работает без неё.

**Save ZIP to Downloads** создаёт свежий архив и сохраняет его в `Downloads/Omodash` на Android 10+. Он доступен для ручной отправки, например через браузер. На более старых версиях можно воспользоваться системной отправкой файла. Лаунчер хранит последние пять архивов у себя; сохранённые пользователем копии в Downloads автоматически не удаляются.

## Что находится в ZIP

- `description.txt`: описание проблемы.
- `device.json`: версия и код сборки, модель/прошивка Android, параметры экрана, статусы разрешений, найденные системные экраны настроек, пакеты/состояния доступных медиасессий.
- `performance.json`: текущие PSS/Java/native heap процесса, накопленное CPU-время, доступная память системы и флаг low-memory. CPU в журнале измеряется по процессу, 100% соответствует одному ядру.
- `events.log`, `events-previous.log`: ограниченный журнал событий лаунчера. Файлы сохраняются при перезапуске приложения и обычном обновлении APK.
- `crash-*.txt`: последние три необработанные ошибки JVM с версией приложения, в которой произошёл сбой.
- `logcat-app.txt`: последние записи текущего процесса, насколько они доступны Android. Ошибки до перезапуска не обязаны оставаться в этом файле — для них нужен сохранённый crash-файл.
- `source-errors.txt`: какие источники не удалось прочитать.
- `logcat-system.txt`: только если устройством уже выдано особое разрешение `READ_LOGS` и пользователь отдельно включил сбор системных логов в форме.

Полный системный журнал недоступен обычному приложению: `READ_LOGS` нельзя получить обычной кнопкой runtime-разрешения. Его выдача требует возможностей конкретной прошивки, привилегированного инструмента или ADB. Отчёт работает и без него. Отсутствие записей не доказывает отсутствие ошибки.

Лаунчер не выгружает файл своих настроек, координаты, содержимое уведомлений, названия треков, скриншоты или список всех приложений. В журнале фиксируются выбранные пакеты медиасессий и ошибки. Системный журнал, если включён, может содержать данные других приложений. Известные поля токенов/паролей маскируются; это не универсальная очистка произвольных системных логов.

Обработчик сохраняет необработанные Java/Kotlin исключения, но не гарантирует отчёты о нативных сбоях, зависаниях ANR, принудительном завершении и отключении питания. При заполненном/неисправном хранилище запись также может не состояться.

Релиз оптимизирован R8. Для расшифровки имён из стека понадобится `mapping.txt` **от версии, указанной в crash-файле**, а не обязательно от текущего приложения. Этот файл публикуется в каждом GitHub Release.

## Доступ к медиа

Нужен доступ notification listener — он позволяет получать информацию о текущем треке и управлять медиасессией. Это не разрешение читать аудиофайлы и не разрешение встраивать Android Auto или CarPlay в плитку.

Лаунчер пробует отдельную страницу доступа для своего сервиса (Android 11+) и общий список notification listeners. Если прошивка не предоставляет эти страницы, появляется объяснение с кнопкой отчёта. Разрешение в этом случае **не выдано**; приложение больше не должно падать или молча игнорировать ошибку. По отчёту можно определить следующий способ настройки конкретной прошивки.

Начиная с 0.0.8, при отсутствии настоящего экрана есть дополнительный путь через уже выданное `WRITE_SECURE_SETTINGS`. На автомобиле: в JCarTools открыть «Выдать права приложениям», выбрать Open Launcher и нажать «Выдать все права». Для специальных прав JCT должен иметь рабочее ADB-подключение; режим Device Owner выдаёт только runtime-разрешения. Название кнопки не гарантирует выдачу всех прав. Лаунчер проверяет фактическое разрешение, а не наличие JCT.

После выдачи вернуться и нажать **Configure vehicle permissions**. Это явное подключение только к `127.0.0.1:5555`, с отдельным ключом лаунчера в приватном `noBackupFilesDir`. Подключение к чужим адресам и произвольный ввод shell-команд не предусмотрены. Если Android показывает запрос авторизации нового ключа отладки, его нужно подтвердить на самом устройстве. При закрытом локальном ADB настройка покажет ошибку; приложение не включает ADB и не обходит авторизацию.

Выполняются команды только для собственного пакета: `WRITE_SECURE_SETTINGS`, `READ_LOGS`, `cmd notification allow_listener` с собственным компонентом и app-op установки APK. Реальный результат проверяется Android API. Изменение app-op установки на Android 11 может завершить собственный процесс; независимая завершающая команда открывает наш MainActivity снова. Ключ и разрешения сохраняются при обычном обновлении APK.

**Enable update helper** — отдельное действие пользователя. При отсутствии настоящего Accessibility экрана и уже выданном `WRITE_SECURE_SETTINGS` добавляется только наш helper с сохранением прочих включённых сервисов. Самопроизвольной выдачи прав при запуске нет. В отчёте виден статус `secureSettingsPermission`.

Одной записи `enabled_notification_listeners` недостаточно на стандартном Android 11: действительное одобрение может храниться в политике NotificationManager. Это подтвердилось повторной проверкой на AOSP API 30. Лаунчер не считает запись значения доказательством доступа; встроенная настройка использует команду NotificationManager и проверяет `isNotificationListenerAccessGranted`.

Для установки APK требуется отдельный app-op `REQUEST_INSTALL_PACKAGES`, который JCT также пытается разрешить через ADB. Если штатный экран недоступен, **Allow app installations** показывает инструкцию JCT. **Recheck permissions** проверяет итог. Загрузка APK разрешена и до выдачи доступа; установка остаётся запрещена до успешной проверки.

Известная автомобильная заглушка `com.android.car.frameworkpackagestubs` не открывается как будто это рабочий экран настроек.

## Попап ALERT и прерывание радио

Автомобильный отчёт 0.0.7 от 27.10.2026 подтвердил отсутствие notification-access экранов, Accessibility-заглушку и запрет установки APK. В нём нет системного журнала (`READ_LOGS=false`), crash-файла или записи OutOfMemoryError. Поэтому происхождение внешнего ALERT и прерывания радио этим архивом **не установлено**; нехватка памяти/CPU не доказана.

В 0.0.8 удалён опрос разрешений каждые 750 мс. Статусы проверяются при первом открытии раздела и явных действиях пользователя; опрос прогресса работает только во время загрузки/установки, когда раздел активен и окно имеет фокус. В фоне цикл отменяется. Это убирает лишние IPC и возможные повторные обращения к OEM контроллеру разрешений, но само по себе не доказывает устранение ALERT.

Первые две минуты после старта процесса автоматически записываются 13 лёгких замеров ресурсов с интервалом 10 секунд; бесконечного мониторинга нет. Запись можно повторить кнопкой **Record performance for 2 minutes** в форме отчёта. После воспроизведения отправить свежий ZIP. Если `READ_LOGS` успешно выдан через JCT, включить сбор системного журнала: в него попадёт до 6000 последних строк, ограниченных последним 1 MiB. Записи потери/возврата фокуса и остановки Activity находятся в `events.log`.

**Settings → Maintenance → Stop launcher process** сначала открывает другой Home (приоритет у штатного DesaySV), удаляет нашу Activity из задач и завершает только собственный PID. Наши listener/helper, приёмники обновлений и провайдер отчётов временно отключаются, иначе системная привязка могла бы немедленно поднять процесс снова. Их прежние состояния восстанавливаются при следующем запуске MainActivity. Другие приложения/службы не отключаются. Если открыть другой Home не удалось, процесс остаётся работать и показывается ошибка. Это не привилегированный Android force-stop: при сохранённом назначении Open Launcher как default Home система может запустить его снова. Настройки, crash-файлы и отчёты при таком выходе сохраняются.

## Получатель по умолчанию при сборке

Скопируй `diagnostics.properties.example` в `diagnostics.properties` и укажи `email=...`. Файл исключён из Git. Адрес войдёт в APK; это не секретное хранилище, пароли и почтовые токены туда не нужны. Если адрес не задан, его можно ввести в форме на устройстве.

## Crashlytics

Firebase Crashlytics пока не подключён. Он будет полезен для автоматической группировки сбоев/ANR и получения отчётов через интернет, но потребует Firebase-проекта, конфигурации приложения и загрузки R8 mapping. Он не заменяет системный журнал автомобиля или описание воспроизведения ошибки. На первом этапе локальный ZIP позволяет исследовать автомобиль без добавления внешнего сервиса.
