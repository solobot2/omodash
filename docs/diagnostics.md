# Диагностика без ноутбука

В Settings вверху расположен **Send / save diagnostic ZIP**. Эта же форма доступна из сообщения об ошибке открытия доступа к медиа в онбординге.

1. Опиши, что нажал и что произошло. Если приложение упало — сначала запусти его снова.
2. Нажми **Send report / Gmail**: ZIP будет создан автоматически.
3. Выбери Gmail и отправь подготовленное письмо с вложением.

На автомобиле нужно установить Gmail и войти в почтовый аккаунт. Получатель подставляется из сборки; его можно изменить в форме. Открытие окна Gmail ещё не означает отправку: нужно нажать Send. Сеть нужна для доставки письма, сбор ZIP работает без неё.

**Save ZIP to Downloads** создаёт свежий архив и сохраняет его в `Downloads/Omodash` на Android 10+. Он доступен для ручной отправки, например через браузер. На более старых версиях можно воспользоваться системной отправкой файла. Лаунчер хранит последние пять архивов у себя; сохранённые пользователем копии в Downloads автоматически не удаляются.

## Что находится в ZIP

- `description.txt`: описание проблемы.
- `device.json`: версия и код сборки, модель/прошивка Android, параметры экрана, статусы разрешений, найденные системные экраны настроек, пакеты/состояния доступных медиасессий.
- `recording.json`, `recorded-events*.log`: ручная ограниченная запись; системная часть прикладывается только по отдельной отметке.
- `performance.json`: текущие PSS/Java/native heap процесса, накопленное CPU-время, доступная память системы и флаг low-memory. CPU в журнале измеряется по процессу, 100% соответствует одному ядру.
- `events.log`, `events-previous.log`: ограниченный журнал событий лаунчера. Файлы сохраняются при перезапуске приложения и обычном обновлении APK.
- `crash-*.txt`: последние три необработанные ошибки JVM с версией приложения, в которой произошёл сбой.
- `logcat-app.txt`: последние записи текущего процесса, насколько они доступны Android. Ошибки до перезапуска не обязаны оставаться в этом файле — для них нужен сохранённый crash-файл.
- `source-errors.txt`: какие источники не удалось прочитать.
- `logcat-system.txt`: только если устройством уже выдано особое разрешение `READ_LOGS` и пользователь отдельно включил сбор системных логов в форме.

Полный системный журнал недоступен обычному приложению: `READ_LOGS` нельзя получить обычной кнопкой runtime-разрешения. Его выдача требует возможностей конкретной прошивки, привилегированного инструмента или ADB. Отчёт работает и без него. Отсутствие записей не доказывает отсутствие ошибки.

Лаунчер не выгружает файл своих настроек, координаты, содержимое уведомлений, названия треков, скриншоты или список всех приложений. В журнале фиксируются выбранные пакеты медиасессий и ошибки. Системный журнал, если включён, может содержать данные других приложений. Известные поля токенов/паролей маскируются; это не универсальная очистка произвольных системных логов.

Обработчик сохраняет необработанные Java/Kotlin исключения, но не гарантирует отчёты о нативных сбоях, зависаниях ANR, принудительном завершении и отключении питания. При заполненном/неисправном хранилище запись также может не состояться.

Релиз оптимизирован R8. Для расшифровки имён из стека понадобится `mapping.txt` **от версии, указанной в crash-файле**, а не обязательно от текущего приложения. Этот файл публикуется в каждом GitHub Release.

## Доступ к медиа и установке обновлений

Доступ notification listener позволяет получать информацию о текущем треке и
управлять медиасессией. Это не чтение аудиофайлов и не встраивание Android Auto /
CarPlay в плитку. Установку APK и хелпер автоподтверждения Android разрешает отдельно.

Для этой автомобильной прошивки нужен [однократный USB-скрипт](usb-setup.md).
Флешка с ключом активирует USB ADB, но не обязательно локальный TCP-порт 5555;
ошибка ECONNREFUSED на машине показала, что прежняя кнопка локальной настройки
не подходит. Пять дополнительных кнопок выдачи прав удалены. В настройках остаются
статусы; Check updates заново проверяет права установки и хелпера.

Скрипт настраивает собственный пакет и проверяет итог. Другие включённые сервисы
не заменяются. Запись enabled_notification_listeners сама по себе не доказывает
одобрение на Android 11 — нужна команда NotificationManager. Красный индикатор
JCarTools относится к его возможности выдавать права другим приложениям; полный
список собственных разрешений JCT этого не гарантирует.

## Попап ALERT и прерывание радио

Автомобильный отчёт 0.0.7 от 27.10.2026 подтвердил отсутствие notification-access экранов, Accessibility-заглушку и запрет установки APK. В нём нет системного журнала (`READ_LOGS=false`), crash-файла или записи OutOfMemoryError. Поэтому происхождение внешнего ALERT и прерывания радио этим архивом **не установлено**; нехватка памяти/CPU не доказана.

В 0.0.8 удалён опрос разрешений каждые 750 мс. Статусы проверяются при первом открытии раздела и явных действиях пользователя; опрос прогресса работает только во время загрузки/установки, когда раздел активен и окно имеет фокус. В фоне цикл отменяется. Это убирает лишние IPC и возможные повторные обращения к OEM контроллеру разрешений, но само по себе не доказывает устранение ALERT.

Первые две минуты после старта автоматически записываются лёгкие замеры CPU /
памяти с интервалом 10 секунд. **Settings → Diagnostics → Record logs for 2 minutes**
теперь находится в самом начале настроек. Эта кнопка запускает не только замеры,
но и отдельную запись logcat. Если READ_LOGS выдан по USB, в окне запуска можно
включить **Include system logs**; иначе записывается только текущий процесс.
Настройки можно закрыть и воспроизвести проблему. Запись ограничена двумя минутами
и двумя файлами по 512 KiB, без фонового сервиса или автоматического перезапуска.

После этого открыть **Send / save diagnostic ZIP**, описать проблему и отправить
через Gmail либо сохранить ZIP в Downloads. Для включения ранее записанного
системного журнала также отметить **Also include system logs** в форме отправки.
Без этой отметки системная запись не прикладывается. В ZIP попадут recording.json
и recorded-events*.log. Файлы остаются после закрытия приложения; новая ручная
запись заменяет предыдущую. Остановка процесса прекращает запись.

**Stop launcher process** открывает другой Home, приостанавливает собственные
listener/helper, receivers и provider, удаляет Activity и завершает собственный PID.
При следующем запуске MainActivity восстанавливаются исходные состояния.
В events.log теперь видны запрос выхода, прежний PID и последующий запуск.
Кнопка не обладает правом системного force-stop; Android может заново открыть
назначенный default Home. Пользователь сообщил, что ALERT продолжался и после
кнопки выхода: без подтверждения отсутствия PID это не доказывает остановку,
и не исключает системное состояние, ранее вызванное работой приложения.

Для точной проверки при USB-подключении: `vehicle_usb.py collect`, затем
`vehicle_usb.py stop`, проверить радио и повторить `collect`.
Режим stop в 0.0.9+ сначала обращается к защищённому DUMP-разрешением приёмнику
нашего приложения, сохраняющему и временно отключающему собственные фоновые
компоненты, а затем делает am force-stop и проверяет отсутствие процессов.
Обычные приложения вызвать этот приёмник не могут. Без подготовки даже AOSP API 30
перезапустил остановленный пакет ради MediaListenerService — это воспроизведено
на тестовом эмуляторе, а не на магнитоле. Команды collect не открывают приложение
и позволяют получить системный журнал даже когда наш процесс остановлен.

## Радио и CarPlay: проверка после 0.0.9

На автомобиле подтверждены подключение медиаслужбы и обновление станции в Any Player
при переключении с руля. Это подтверждает получение данных; работа команд Next /
Previous / Play отдельно не подтверждена. В исследованных исходниках штатного
SVLauncher управление медиа идёт через VDB, поэтому нельзя считать стандартные
TransportControls эквивалентом штатных кнопок руля.

В 0.0.10 меню источников виджета содержит Open CarPlay / Open Android Auto при
назначенном приложении, независимо от активного радио. Назначение само по себе
не переключает радио-виджет в экран CarPlay. Ошибки запуска больше не скрываются.

Для AM/FM сначала включить штатное радио, открыть выбор радиоисточника и нажать
Use the currently playing source as radio. Это назначает конкретную живую сессию,
которую уже показывает Any Player, без угадывания служебного пакета из списка.
Открытие её экрана использует [MediaController.getSessionActivity](https://developer.android.com/reference/android/media/session/MediaController#getSessionActivity()),
когда владелец сессии предоставил такой переход.

Для следующего теста: записать системный журнал, попробовать каждую медиакнопку
по одному разу и создать ZIP с системными логами. В events.log будут события
MediaCommand: пакет, команда, стандартные action-флаги и исключение при наличии.
В device.json → mediaSessions дополнительно попадают action-флаги, идентификаторы
custom actions и пакет PendingIntent для открытия экрана. Отправка команды без
исключения ещё не означает, что OEM-радио её выполнило.

Опрос прогресса отключён для радио без длительности и для Activity в фоне.
Это устранение лишних запросов, а не доказанное объяснение внешнего ALERT.

## Получатель по умолчанию при сборке

Скопируй `diagnostics.properties.example` в `diagnostics.properties` и укажи `email=...`. Файл исключён из Git. Адрес войдёт в APK; это не секретное хранилище, пароли и почтовые токены туда не нужны. Если адрес не задан, его можно ввести в форме на устройстве.

## Crashlytics

Firebase Crashlytics пока не подключён. Он будет полезен для автоматической группировки сбоев/ANR и получения отчётов через интернет, но потребует Firebase-проекта, конфигурации приложения и загрузки R8 mapping. Он не заменяет системный журнал автомобиля или описание воспроизведения ошибки. На первом этапе локальный ZIP позволяет исследовать автомобиль без добавления внешнего сервиса.
