# Android Auto, CarPlay и штатные приложения

Production использует приёмники из прошивки Omoda 9 HW110 / Android 11:

| Назначение | Пакет |
| --- | --- |
| Музыка и радио | `com.desaysv.svaudioapp` |
| Камера AVM | `com.desaysv.ivi.vds.rvc` |
| Телефон | `com.desaysv.bluetooth.phone` |
| Android Auto | `com.google.android.projection.sink` |
| CarPlay | `com.desaysv.vehicle.carplayapp` |

Эти назначения заданы по умолчанию. При обновлении заполняются пустые заводские
ярлыки и назначения проекции/радио; пользовательские назначения сохраняются.
Значок камеры отправляет тот же VDB `AVM_ICON_PRESS`, что заводской SVLauncher,
поскольку камера не является обычной запускаемой Activity. Используется VDB-клиент
установленного заводского лаунчера; бинарники прошивки в APK не копируются.
Для смены приложений используйте настройки и долгое нажатие ярлыка.
Пресеты других автомобилей пока не добавлены.

## Android Auto через локальный TCP ADB

Android Auto открывается в области плиток Home. Шапка с закрытием и боковая панель
остаются доступны. Временный shell-помощник создаёт виртуальный дисплей, запускает
целую Activity штатного AA-приёмника и передаёт касания этому дисплею. При закрытии
панели, навигации, изменении размера или смерти лаунчера дисплей и помощник
освобождаются. Ни скриншоты, ни изменение AA-декодера для этого не нужны.

Лаунчер сам подключается исключительно к `127.0.0.1:5555` и запускает помощник из
собственного подписанного APK. Для ADB создаётся отдельный ключ в приватном
`noBackupFilesDir` приложения. Ключ не включается в APK, Git, диагностический ZIP
или резервное копирование. Канал Binder защищён `DUMP`, проверкой shell UID 2000
и текущей сессии; произвольных команд и адресов подключения в интерфейсе нет.
Сам лаунчер остаётся обычным Android-приложением.

Однократно с подключённым по USB ноутбуком:

```sh
python3 tools/vehicle_usb.py setup
python3 tools/vehicle_usb.py enable-android-auto
```

Затем открыть Android Auto в Omodash и подтвердить запрос USB-отладки на экране
ГУ, если он появится. `enable-android-auto` выполняет `adb tcpip 5555`: adbd может
слушать сетевые интерфейсы устройства, хотя сам Omodash подключается только локально.
После полной перезагрузки может понадобиться снова включить TCP ADB через USB;
запись постоянных системных свойств и root для этого релиза не используются.
Обычный `setup` сохраняет прежнее поведение и сам TCP ADB не включает.

Путь контейнера рассчитан на Android 10/11. Наличие штатного AA-пакета и работа
локального ADB обязательны. Если соединение или авторизация недоступны, панель
показывает причину, которую также можно включить в диагностический отчёт.
CarPlay открывает штатное приложение через его заводской action.

Экспериментальные decoder/Surface API, тестовый `com.omodash.aareceiver`,
debug broadcast-команды и PiP из production-кода удалены. На физическом ГУ
нужно отдельно подтвердить штатный AA-сеанс, аудио, сон/пробуждение и доступность
TCP ADB после полной перезагрузки; проверки эмулятора этого не доказывают.

## Медиакарточка и радио

CarPlay / AA получают пары DOWN/UP media keys, соответствующие callback их
заводских MediaSession. Штатное радио может читаться и управляться через
установленный Desay VDB-клиент; MediaSession остаётся запасным источником.
Кнопки проекции доступны также при активном радио. Запись производительности
и отправка диагностического ZIP сохранены в настройках. У назначенного радио
показывается «Open radio», без повторного запроса назначения. Кнопки радио и музыки
обращаются к разным источникам общего штатного аудиоприложения. Для камеры
сохраняется заводское ограничение скорости менее 30 км/ч; при отсутствии данных
скорости команда не отправляется.

## Проверка 30 октября 2026

- Unit: 16 проверок миграции сетки, масштаба, ADB-пакетов/ключа и медиаданных.
- Python: 23 проверки USB-инструментов и публикации.
- Android 11: RSA AUTH/public key и повторное подключение через реальный loopback
  socket; обычный app UID не получает shell bridge; запуск, закрытие и повторное
  открытие Activity-контейнера; медиакнопки, медиакарточка и диагностика; 100/200%.
- Оптимизированный release установлен поверх 0.0.13-dev без очистки данных.
  Через штатную кнопку Android Auto проверены запуск shell-помощника, отдельный
  дисплей с целой Activity/SurfaceView тестового APK, касание и завершение процесса
  после закрытия. В release entry point сохранён после R8.
- На данном эмуляторе adbd использует emulator transport, поэтому для теста
  контейнера использован `adb reverse tcp:5555 tcp:5557`. Это проверяет клиент,
  протокол и helper, но не доказывает прямую TCP-доступность adbd на ГУ.
- Тестовая Activity использует package ID штатного AA только в изолированном
  эмуляторе. Она не является AA-сеансом, не публикуется и не включается в APK.
